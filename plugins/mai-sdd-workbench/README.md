# SDD workbench / SDD 工作台

English | [中文](README.zh.md)

Read my-ai-infra Features, BRIEF, PRD, technical designs, design reviews, code reviews, and test plans inside DSH. The workbench supports Chinese and English, Markdown, refresh, and pagination. It is read-only, makes no model requests, and requires no API key.

## Installation and use

1. Use Node.js 24.9+ and pnpm 11.28.5. Follow the DSH root README to install dependencies and build, then run `pnpm dsh web` at the repository root.
2. In DSH, use **Plugins → Add plugin** to select this directory (the absolute path to `plugins/mai-sdd-workbench`). The repository includes the built `client.js`; no separate plugin build is needed for initial use.
3. Create a DSH workspace and session for the target repository. Run `mai init` at that repository's root, then use the my-ai-infra Skills to create `mai-specs/NNN-slug`.
4. Open **SDD workbench** from the sidebar and select the session's workspace, Feature, and document. Workbench selections do not change the current chat session. Click **Refresh** after editing documents externally.
5. Click **Load more** when a document has unread pages. Click **Back to conversation** to return to chat.

Only standard my-ai-infra document paths are supported. Custom FEATURE_LAYOUT paths, editing, stage execution, file watching, and Mermaid/math rendering are outside this version's scope. Phase is a BRIEF declaration, not proof of acceptance. Raw HTML is displayed as text; images and local links do not open automatically. File access follows DSH permissions; check the session workspace and retry if reading fails.

## Development and verification

Run these commands in this directory (the separate npm lockfile does not modify the DSH pnpm workspace):

```sh
npm ci --ignore-scripts
npm run build
npm test
```

`react` is used only for development tests; DSH provides it at runtime. `marked` is bundled into the browser artifact. Development dependencies have fixed versions, and production loading uses no external CDN. Restart DSH after rebuilding to load the updated browser code. Enable or disable the plugin on the **Plugins** page; DSH manages the persistent profile configuration without manual edits.

See the [test plan](../../mai-specs/999-mai-sdd-workbench/test/TEST_PLAN.md) for business verification steps and actual results, and the [Feature brief](../../mai-specs/999-mai-sdd-workbench/BRIEF.md) for requirements and design. Automated results and real Host acceptance are recorded separately.

## Files

- `src/client.jsx`: DSH module and slot registration and disposal.
- `src/model.js`: standard document paths, Feature/BRIEF reads, and consistent pagination.
- `src/views.jsx`: page interactions and cancellation of old requests.
- `src/markdown.js`: marked tokens rendered as React without HTML injection.
- `client.js`: directly installable browser artifact generated by build.mjs.
- `tests`: focused behavior tests and owner-local expected output.

The icon is an original SVG for this assignment. DSH provides its own UI and React.
