## 范围与依据

唯一需求与验收来源是 [PRD](../spec/PRD.md) 的 AC-01 至 AC-06；本计划引用这些编号，不另设一套完成标准。验证对象是在 DSH 内安装、启用的本地工作台插件，覆盖工作区与 Feature 导航、六类标准文档阅读、手动刷新、异常恢复、分页及插件生命周期。

技术依据为 [技术方案](../design/TECH_DESIGN.md) 和 [设计评审](../review/design_review.md)。设计评审的固定文档路径、Unicode 目录名、旧请求隔离及分页版本一致性条件纳入相应开发测试与业务补验；这些技术条件不取代 PRD 的验收标准。

规划基线为 DSH 提交 实施前 HEAD（DSH 0.2.2-rc.3），工作区已有未提交的 my-ai-infra 初始化和本 Feature 规格。执行时须补记实际插件版本及相关未提交文件指纹；此基线不能代表之后代码的通过证据。

课件第 6 页要求设计和测试计划成为实现上下文，第 11 页要求同一验收标准对齐规格、代码与证据，第 37、49 页强调实际结果。依照这些要求，单元测试、构建、插件安装返回值和真实 DSH 页面观察分别记录；任何一项不能单独替代完整业务链路。

## 执行准备与数据

- 使用已授权的本地 DSH Web profile；执行前记录实际地址和登录状态，不在证据中保存本地认证 token。插件无需模型 API key，不发送模型请求。
- 浏览器自动化启动遵循仓库规定：`pnpm dsh web --patch apps/web/tests/pin-browse-picker.overlay.yml`。启动与重启由主任务协调，避免与用户现有进程争用端口或会话。
- 使用一个隔离验收工作区及其 DSH 会话；建议放在作业根目录的 `.setup/sdd-acceptance-workspace`。此目录仅在实际执行需要时创建，不能把验收样例当作正式 Feature 交付记录。另准备第二个空工作区及会话，用于检查范围切换。保留原聊天会话，测试完恢复。
- 隔离目录下准备 `mai-specs/999-acceptance-alpha` 和 `mai-specs/998-acceptance-beta`。简报标题分别为“验收样例 Alpha”“验收样例 Beta”，Phase 分别使用 `draft`、`review`；正文各有唯一标记 `ALPHA-CONTENT`、`BETA-CONTENT`，便于独立对照磁盘。准备标准目录里的六类文档，并有意缺少 Beta 的一个阶段文档。
- 在 `mai-specs` 放入 `_templates`、`README.md`、`ROADMAP.md` 及非 Feature 目录作为过滤对照。附加样例使用中文 slug 并缺少 BRIEF Phase，用于验证 Unicode 名称和“未标注”；不得把缺少字段解释成已完成。
- Markdown 样例包含中文标题、无序列表、代码块、两列表格、长路径、长行、原始 HTML、图片语法与本地相对链接。原始 HTML 使用无害可识别标记；图片使用隔离环境中可核对请求记录的地址，避免向第三方发送数据。
- 长文档按实际宿主分页大小准备，至少跨两页，连续行号和首尾唯一标记应由独立文本生成。记录实际行数和文件内容，不能用被测读取函数生成期望。
- 所有临时文件仅由执行者在隔离工作区操作；准备前检查已有同名路径，遇到用户文件保留并另选路径。恢复只清理本次创建且已核对的文件，不删除正式 `mai-specs` 或修改系统权限设置。

## 待验业务用例

### TC-01：从 DSH 打开工作台并返回对话

- 关联需求：AC-01。
- 前提与数据：插件已通过 DSH 支持的安装入口安装并启用；已有一个可返回的聊天会话。
- 操作步骤：
  1. 在实际 DSH 页面找到“SDD 工作台”侧栏入口并打开。
  2. 观察工作台与 DSH 原有侧栏、主区域的关系。
  3. 点击“返回对话”，再通过侧栏重新打开。
- 预期结果：页面在 DSH 原生主区域内显示，入口可重复使用；返回后恢复对话界面，不生成新模型请求或修改会话内容。
- 验证方式与证据：实际浏览器操作；保存包含 DSH 外框、工作台及返回后状态的必要截图或观察记录。安装成功信息仅作为前提，不能算本用例通过。

### TC-02：工作区、Feature 和标准文档对应真实磁盘内容

- 关联需求：AC-02。
- 前提与数据：隔离工作区包含两份带唯一标记的 Feature；第二个空工作区已有会话。
- 操作步骤：
  1. 选择隔离工作区对应的会话，检查 Feature 列表。
  2. 先选择 Alpha，再选择 Beta，逐一选择已准备的标准文档。
  3. 对照磁盘简报的标题、Phase 和文档唯一标记。
  4. 切换到第二个工作区，再切回；检查当前聊天会话是否仍保持原选择。
  5. 查看中文 slug、没有 Phase 的样例。
- 预期结果：只列标准 `NNN-slug` Feature，中文 slug 可正常选择和读取；模板、普通文件和非 Feature 目录不混入。选择、标题、Phase 和正文属于同一工作区与 Feature；六类入口指向相应标准路径。工作台的范围选择不改变当前聊天会话；缺少 Phase 显示未标注，不展示虚假通过或完成率。
- 验证方式与证据：记录选定会话的工作区路径、Feature 及唯一内容标记；保留磁盘内容与对应页面截图，不仅检查列表条数。

### TC-03：Markdown 可读且不执行文档中的活动内容

- 关联需求：AC-03；PRD 第 5 节。
- 前提与数据：Markdown 样例已作为选中 Feature 的标准文档，原始文件内容已独立保存。
- 操作步骤：
  1. 打开样例，查看标题、列表、代码块和表格。
  2. 查看原始 HTML 标记、图片及本地相对链接的处理。
  3. 检查代码块中的 HTML 仍作为代码显示；观察图片目标是否有自动请求。
- 预期结果：语义结构可读，代码空白与表格列不丢失。原始 HTML 不执行，图片不自动加载，文档链接不自动触发其他本地文件读取。允许安全地显示为文本或非活动内容，不凭视觉相似判断脚本安全。
- 验证方式与证据：结合实施阶段安全渲染测试和实际页面检查；保留样例内容、渲染截图及可用请求观察。若无法观察网络请求，明确图片自动加载这一项仍待核验。

### TC-04：刷新读取磁盘上的最新文档及 Feature 列表

- 关联需求：AC-04。
- 前提与数据：Alpha 当前文档显示 `ALPHA-BEFORE`；测试者可编辑隔离文件。
- 操作步骤：
  1. 在工作台保持当前文档打开，在外部把唯一标记改为 `ALPHA-AFTER`，并修改简报标题或 Phase。
  2. 在隔离 `mai-specs` 新增一份合法 Feature 样例。
  3. 点击工作台“刷新”，不重载浏览器整页。
  4. 再选择 Beta，核对它自己的内容。
- 预期结果：刷新后显示新正文和新简报信息，Feature 列表出现新样例；Beta 仍显示自己的标记。读取中有可见状态且刷新不能重复提交；不要求自动监听磁盘。
- 验证方式与证据：保存变更前后磁盘标记、同一页面刷新前后观察和新增 Feature 的列表状态。
- 清理：恢复本用例改动或在验收结束后清理隔离样例。

### TC-05：快速切换时旧响应不覆盖当前选择

- 关联需求：AC-04；PRD 第 4 节。
- 前提与数据：Alpha、Beta 含不同标记；使用可控的测试替身或隔离环境延迟制造响应顺序，禁止改业务标准求绿。
- 操作步骤：
  1. 打开 Alpha 文档并在其读取未完成时切换到 Beta。
  2. 分别重复快速切换文档、切换工作区及刷新后切换。
  3. 在较早请求最后返回的情况下，观察当前标题、路径、Phase 与正文。
- 预期结果：最后选择的范围始终与呈现内容一致，早期响应不回写；当前加载或错误状态也不被旧请求替换。离开页面后无旧请求把页面重新打开。
- 验证方式与证据：实施阶段应提供可重复的异步顺序测试；实际页面快速切换作为补充观察。若未能实际制造乱序，不能仅凭一次快速点击宣称乱序场景通过。

### TC-06：没有会话、没有 mai-specs 或没有 Feature

- 关联需求：AC-05。
- 前提与数据：分别准备可控的无可用会话环境、没有 `mai-specs` 的隔离工作区，以及空 `mai-specs` 工作区；不删除用户现有会话来制造数据。
- 操作步骤：
  1. 在无可用会话状态打开工作台。
  2. 选择尚未初始化的工作区。
  3. 在外部创建空 `mai-specs` 后刷新，再创建标准样例后刷新。
- 预期结果：分别显示创建会话、在仓库根目录运行 `mai init`、暂无 Feature 的对应状态。状态与实际原因一致，页面不崩溃；补齐条件并刷新后可继续导航。无会话场景若无法隔离，则明确未执行，保留其开发测试要求。
- 验证方式与证据：实际可用空状态截图与恢复路径记录；无会话的测试替身结果须标明不能替代真实环境检查。

### TC-07：缺失文档或读取失败后能够恢复

- 关联需求：AC-05。
- 前提与数据：Beta 缺少一个阶段文档；读取拒绝使用现有权限能力或可控测试替身，不随意调整用户文件 ACL 或系统策略。
- 操作步骤：
  1. 选择 Beta 缺少的文档。
  2. 在隔离目录创建该文档并点击刷新。
  3. 制造一次读取拒绝或传输失败，再解除条件并刷新。
- 预期结果：缺文件明确表示此阶段文档尚未生成，不伪装成加载成功；读取失败有可执行的重试提示，不显示其他 Feature 的旧正文。补齐文件或解除失败后可以恢复阅读，工作台仍可操作。
- 验证方式与证据：缺失到恢复使用实际页面和磁盘文件核对；拒绝/传输失败记录实际注入条件与测试层级。若仅 Mock 验证拒绝，不声称真实权限链路已通过。
- 清理：恢复临时文件和测试失败条件。

### TC-08：分页与目录截断没有冒充完整结果

- 关联需求：AC-05；PRD 第 5 节。
- 前提与数据：有跨至少两页的连续行号文档；实施阶段提供实际读取分页大小及目录上限信息。
- 操作步骤：
  1. 打开长文档，核对第一页内容和未读取完的提示。
  2. 使用页面提供的加载下一页操作，直到读到文件末尾。
  3. 核对页间行号、边界标记和末尾标记。
  4. 在隔离测试条件下触发目录结果截断，检查提示；不为此创建海量真实文件或改用户全局配置。
  5. 重新打开长文档，在第一页读取后外部修改文件，再尝试追加下一页。
- 预期结果：首屏不把部分正文当成全文；后续页能追加且行序无缺失、无重复，到末尾后显示完整状态或不再提供无效加载。目录被宿主截断时明确提示列表不完整。读取失败后能够重试，不能把失败页当成结束。同一文档的后续页版本变化时不拼接两版正文，并提示刷新恢复；本分支依据设计评审条件核验。
- 验证方式与证据：长文档实际页面与独立文件内容对比；目录截断可由开发测试覆盖，需标明是否实测宿主。页数和限制值来自当前实现及宿主配置，不另设性能阈值。

### TC-09：实际 DSH 中的主题、窄布局与键盘操作

- 关联需求：AC-01、AC-03；PRD 第 4 节。
- 前提与数据：工作台打开，样例包含长标题、长路径和宽代码/表格。
- 操作步骤：
  1. 使用 Tab 定位工作区、Feature、文档、刷新和返回控件，并使用 Enter/Space 操作。
  2. 在明暗主题下查看正文、选中态、加载态和错误提示。
  3. 缩小可用主区域，观察控件换行、滚动、长文本及操作可达性；恢复原宽度与主题。
- 预期结果：控件有名称和可见焦点，选中文档状态可辨；颜色在两种主题下可读。窄区域操作不被裁掉，长内容不会挤掉返回或刷新，表格和代码可以局部滚动。检查实际组装页面，不以单独组件截图代替。
- 验证方式与证据：记录检查的主题、实际可用宽度和相关页面状态，保留需要说明问题或结果的截图。没有 PRD 来源的固定宽度或延迟指标不作为新增门槛。

### TC-10：禁用、启用与重启后的插件生命周期

- 关联需求：AC-06。
- 前提与数据：插件通过正常 Plugins 管理流程安装；当前无进行中的模型任务；执行者能协调重启 DSH。
- 操作步骤：
  1. 工作台正在显示时，通过 Plugins 禁用插件，检查入口、页面和回退结果。
  2. 重新启用，再次打开并读取样例文档。
  3. 先返回对话或打开另一个 DSH 主页面，再禁用工作台插件，检查既有页面是否被错误切换。
  4. 重新启用并使用原 profile 正常重启 DSH，重新连接后打开工作台。
- 预期结果：禁用后注册入口与工作台页面撤销；只有被卸载的工作台正在显示时才回到对话，其他主页面不被重置。启用后没有重复入口，重启后安装与启用状态保留且可重新读取文件。若宿主明确要求重启，记录状态并完成重启后再判定，不从日志推定已激活。
- 验证方式与证据：保存管理页面的实际状态、前台页面变化、重启后的入口及文档观察；必要时记录加载错误。仅进程存在或安装结果成功不足以通过。
- 清理：恢复插件启用状态、原会话及用户主题等偏好；不卸载用户原有插件。
